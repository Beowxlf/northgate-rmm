# RDP password verification adapter

`northgate_rmm.credential_rdp.FreeRDPNLAVerifier` implements the optional rotation executor's asynchronous `verify(target=..., parameters=..., fields=...) -> bool` contract. It performs one fresh NLA authentication using FreeRDP, without starting an interactive desktop. It does not authorize a rotation: the caller must first verify the human session, fresh MFA, explicit rotation grant, exact enrollment and account binding, durable staged vault version, and the privileged worker's independent account/SID verification.

## Deployment contract

Construct `FreeRDPNLAVerifier(executable, executable_sha256, timeout_seconds=20)` only after qualification. Optional paired arguments `xvfb_executable` and `xvfb_sha256` enable the private virtual-display adapter for packaged clients that require X. The configuration is owned by deployment; no executable, hash or command argument is accepted from browser or MCP requests. Each executable must be a resolved absolute Linux ELF path, owned by root, without set-user/group-ID bits or group/other write permission, under equally protected parent directories. Each invocation hashes the executables and retains their descriptors through execution. The adapter permits one verification at a time and enforces a 1–30 second deadline plus bounded termination cleanup. No helper is installed or enabled by this module.

Use a reviewed FreeRDP package. The inspected FreeRDP 2.11.7 X11 client opens the X display during client construction; the inspected 3.20.0 client skips X setup for authentication-only connections. Without the optional display adapter, a client requiring X fails closed. Qualification must cover the installed client and its packaged runtime libraries; the executable hash alone does not attest every shared library. [FreeRDP 2.11.7 client source](https://raw.githubusercontent.com/FreeRDP/FreeRDP/2.11.7/client/X11/xf_client.c), [FreeRDP 3.20.0 client source](https://raw.githubusercontent.com/FreeRDP/FreeRDP/3.20.0/client/X11/xf_client.c).

When configured, Xvfb starts separately for each verification, chooses an unused display through `-displayfd`, uses an 800×600 virtual framebuffer in memory, disables TCP with `-nolisten tcp`, and requires a fresh 128-bit MIT authentication cookie in private mode-0600 authority files. It never uses `-ac`, shared-memory framebuffer files or a desktop manager. Neither cookie nor password appears in arguments or output. The FreeRDP process receives only the display identifier and authority-file path. Unexpected Xvfb exit, excess output or cancellation fails verification. Both processes, authority files and temporary directories are cleaned up. Preserve `PrivateTmp=yes` and AF_UNIX permission in the enclosing service. [Debian X server options](https://manpages.debian.org/bookworm/xserver-common/Xserver.1.en.html), [Debian Xvfb manual](https://manpages.debian.org/bookworm/xvfb/Xvfb.1.en.html).

Required target: a real `RemoteTarget` for the exact enrolled private IPv4 address and RDP port 3389. Required parameters: `security=nla` and exactly one `cert-fingerprints=sha256:aa:bb:...` pin containing 32 bytes. TLS-only mode, certificate ignore, TOFU and authentication bypass are rejected. Fields must contain an explicit local username, machine domain and printable ASCII candidate password of 1–128 characters, matching the generated-password worker contract. Passwords are passed only on standard input; they are never included in command arguments, environment, returned results or logging. Other Guacamole parameters are not forwarded.

The process gets a new private temporary home, no inherited environment or Kerberos cache, no RDP file, no automatic reconnect, and no clipboard redirection. Raw client output is bounded to 64 KiB in memory and discarded. A timeout, cancellation, output overflow, missing executable, hash mismatch or authentication failure cannot produce success. The executor calls `preflight(...)` before staging/dispatch to validate arguments and both executable hashes without sending credentials. This does not guarantee later network availability; `verify(...)` repeats the integrity checks and performs the fresh connection after the worker change.

## Why not use Guacd ready or display frames?

Guacamole may duplicate its initial display while FreeRDP is still connecting. The RDP join handler checks whether a display exists; it does not require an authenticated RDP instance. Therefore `ready`, an image or a synchronization instruction alone is insufficient evidence that a candidate password authenticated. [Guacamole 1.6 RDP client source](https://raw.githubusercontent.com/apache/guacamole-server/1.6.0/src/protocols/rdp/client.c), [Guacamole 1.6 RDP connection source](https://raw.githubusercontent.com/apache/guacamole-server/1.6.0/src/protocols/rdp/rdp.c).

The adapter forces NLA and requires both process exit zero and the FreeRDP core's authentication-only success result; conflicting authentication result lines fail. This marker is generated after `rdp_client_connect`, not by the browser protocol's initial display. The exact installed package must retain the expected marker format; an unfamiliar format fails closed. [FreeRDP core connection source](https://raw.githubusercontent.com/FreeRDP/FreeRDP/2.11.7/libfreerdp/core/freerdp.c), [FreeRDP command-line security and stdin parsing](https://raw.githubusercontent.com/FreeRDP/FreeRDP/2.11.7/client/common/cmdline.c).

## Required qualification before enabling

1. With a disposable, explicitly authorized local account, verify correct credentials and the exact enrollment-bound certificate pin return true. Confirm the worker reports the intended account SID.
2. A single deliberately incorrect candidate must return false. Account-lockout settings must permit this bounded negative test; never loop guessed credentials.
3. A deliberately incorrect certificate pin must return false before successful authentication. Restore the configured pin; do not change the workstation certificate for this test.
4. Confirm timeout and request cancellation terminate the verifier and do not promote the staged vault version.
5. Check process arguments, service logs and public receipts contain no candidate password. Qualify under the actual service UID and packaged library versions.
6. With Xvfb configured, confirm a client lacking its authentication cookie is rejected, TCP is not listening, and neither helper process remains after a positive, negative or cancelled verification.

The 39 focused Python tests exercise fixed arguments, certificate/authentication rejection, stdin isolation, output limits, false success markers, preflight descriptor cleanup, virtual-display authority records, unexpected display-server exit and cancellation cleanup with synthetic process fixtures. They are not a substitute for the Linux package qualification above. The verifier remains an optional dependency and no production or lab account is rotated by these tests.
